# 0002 -- Optional live binding, enforced paths (Q-LIVE)

Status: accepted (C-25, C-17).

## Context

A gate compares a frozen kernel (A) with a candidate (B). The candidate is usually the live source file of the
consumer's repo, but a gate may also pin both sides as frozen files. A hosted run must never depend on a path that
exists only on the maintainer's machine.

## Decision

- The live path of a `frozen[]` entry is optional. With one, the live file must be byte-identical to the frozen one
  (else STOP ANCHOR); without one the gate is frozen only and the HEADER prints `live not bound (frozen only)` (C-25).
- Relative paths resolve against the gate file's directory. An absolute path is allowed locally and is STOP HARNESS
  when `GITHUB_ACTIONS=true` (C-25).
- Nothing the workflow template runs may depend on a local absolute path, and a harness failure on a runner (a failed
  step before the gate, a red selftest, a STOP, a crash) is NO VERDICT, never host evidence (C-17).
- `examples/ab.gate.mjs` stays frozen only, so the package's own dogfood workflow needs no live file (C-24).

## Consequences

- A hosted verdict is reproducible from the repo alone. A research lane that binds absolute local paths (the R1 lane)
  cannot run hosted; its re-proof is therefore local (C-35).
- The selftest live-drift row prints `n/a (frozen only)` for a frozen-only gate and passes only when the frozen-only
  HEADER line is present in the same run (C-30).

## Alternatives rejected

- Making live mandatory: it would block a gate whose candidate is itself a frozen file.
- Rejecting absolute paths everywhere: local research runs need them.
